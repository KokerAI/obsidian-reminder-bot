# 🤖 Personal Obsidian Telegram Reminder Bot

![obsidian.jpg](assets/images/obsidian.jpg)

Личный Telegram-бот для отслеживания дедлайнов и задач из хранилища [Obsidian](https://obsidian.md/). 
Бот читает заметки, парсит свойства (YAML frontmatter) и инлайн-задачи (чекбоксы, списки, Dataview), а затем присылает уведомления по расписанию.

> ⚡️ **Архитектура:** Бот спроектирован по принципу DRY (Don't Repeat Yourself). Парсинг диска вынесен в кэшируемый модуль, сортировка и группировка централизованы в единой функции, а запись пользовательских настроек происходит атомарно (через временный файл с последующим `os.replace`) для защиты от повреждения JSON при сбое питания.

## ✨ Основные возможности

- **📅 Умный фильтр дедлайнов:** Гибкая шкала времени (1 день, 2 дня, 4 дня, Неделя, 2 недели, Месяц, Все) + отдельная кнопка для 🔴 Просроченных задач.
- **🔴 Лимит просрочек:** Настройка `OVERDUE_DAYS_LIMIT` в конфиге, чтобы не засорять список древними задачами (по умолчанию — за последний месяц).
- **📊 Настройки отображения:** Выбор порядка сортировки (Сначала новые/старые, Сверху вниз/Снизу вверх), группировка по источникам и динамическая сортировка групп по срочности.
- **🌐 Поддержка часовых поясов:** Бот работает в твоей таймзоне (например, `Europe/Moscow`), независимо от того, где запущен сервер. Все вычисления внутри приводятся к `naive datetime` (без tzinfo) для корректных сравнений.
- **⏱️ Watchdog (мгновенное кэширование):** При установке библиотеки `watchdog` бот моментально сбрасывает кэш при сохранении файлов в Obsidian, не дожидаясь таймера в 30 секунд. Снижает нагрузку на диск и делает работу мгновенной.
- **🔍 Гибкий поиск дат:** Атомарные переключатели для чекбоксов, списков и тела заметки.
- **🧩 Поддержка Dataview и Tasks:** Распознавание инлайн-полей (`[due:: YYYY-MM-DD]`) и эмодзи-маркеров (`📅`, `⏳`, `🛫`).
- **🗓️ Голые даты:** Поиск дат без маркеров (строго в конце строки).
- **🪄 Умный Fallback дедлайнов:** Если в YAML нет даты, бот возьмет первую дату из невыполненной подзадачи для отображения в карточке (визуальный якорь), но **не будет спамить** уведомлением по этому fallback-дедлайну — уведомления прийдут точно по времени конкретной подзадачи.
- **📁 Выбор источника для парсинга:** Популярные плагины Projects, Kanban, Tasks + возможность создания кастомных источников.
- **📂 Динамические подпроекты:** Папка `Projects` работает как контейнер. Бот рекурсивно сканирует все заметки (включая корень папки и подпапки) и создает меню выбора проекта. Каждый проект может иметь свои уникальные статусы!
- **🔀 Виртуальные группы Kanban:** Настройка вывода Канбана (С группировкой / Без группировки, выбор порядка бордов и заметок). Бот автоматически очищает служебный синтаксис `%% kanban-plugin` и нормализует метки `**Complete**` в выполненные чекбоксы `[x]`.
- **🏷️ Отображение колонок Kanban:** Бот запоминает, в какой колонке находится карточка, и добавляет имя колонки в начале текста в Telegram (например, `[In Progress] Сделать рентген`).
- **⏰ Гибкие уведомления:** Настройка интервалов + уведомление "В момент начала" + **Grace Window (2 мин)** — окно защиты от пропусков, если cron-задача задержалась ровно на 1 минуту.
- **🔕 Беззвучные уведомления:** Режим тихих пушей (без звука и вибрации), включается прямо в меню `🛎️ Уведомления`.
- **🌅 Утренняя сводка (Daily Digest):** Ежедневная отправка списка задач на сегодня и просроченных в заданное время. Включается в «Дополнительных настройках».
- **🌙 Тихие часы:** Блокировка отправки уведомлений в ночное время. Теперь включается прямо в боте (в «Дополнительных настройках»), а время задается в конфиге.
- **🚦 Сортировка по приоритетам:** Опциональная вторичная сортировка задач (внутри одной даты) по приоритетам плагина Tasks (`⏫`, `🔼`, `🔽`, `⏬`) или полям YAML.
- **🎛️ Динамическое меню:** Кнопки статусов генерируются на лету из конфигурационного файла.
- **🚫 Черный список:** Игнорирование заметок по тегам (например, `#no_bot`).
- **💾 Умное кэширование и защита данных:** Кэш диска на 30 сек (чтобы планировщик не убивал SSD каждую минуту), автобэкап при повреждении `settings.json`, ограничение памяти (хранение только 500 последних ключей нотификаций с сортировкой от свежих к старым).
- **🛡️ Централизованная логика (DRY):** Единая точка сортировки, группировки и пагинации предотвращает баги со рваными страницами.
- **🧬 Автомиграция настроек:** Бот автоматически обновляет старые ключи сортировки (`asc/desc/far`) на новые (`new/old`) при загрузке `settings.json`.
- **⚙️ Управление уровнем логирования:** Уровень детализации логов (`INFO`, `DEBUG`, `WARNING`) теперь задается в `config.py` и применяется на лету ко всем модулям.
- **👻 Скрытие выполненных задач:** Выполненные задачи (статусы `Done`/`Archive`) автоматически скрываются из списков "Дедлайны" и "Утренняя сводка", чтобы не засорять актуальные планы.
- **⏳ Настройка горизонта времени:** Гибкая настройка в конфиге: показывать задачи за "24 часа" от текущего момента (скользящее окно) или строго "до конца дня" (до 23:59) — отдельно для кнопок дедлайнов и для утренней сводки.

## ⚙️ Установка и запуск

1. Клонируй репозиторий и перейди в папку:
   ```bash
   git clone https://github.com/KokerAI/obsidian-reminder-bot.git
   cd obsidian-reminder-bot
   ```

2. Создай и активируй виртуальное окружение, установи зависимости:
   ```bash
   python3 -m venv venv
   source venv/bin/activate  # Для Windows: venv\Scripts\activate
   pip install .
   ```
   *(Для работы мгновенного обновления кэша (Watchdog) выполни: `pip install watchdog`)*

3. Создай файл `.env` в корне проекта:
   ```env
   BOT_TOKEN=твой_токен_от_BotFather
   CHAT_ID=твой_Telegram_ID
   OBSIDIAN_VAULT_PATH=/путь/к/твоему/хранилищу/Obsidian
   TASKS_FOLDER=Tasks
   PROXY_URL=http://127.0.0.1:10809  # Опционально
   ```

4. Запусти бота:
   ```bash
   python run.py
   ```
   *Запуск осуществляется через `run.py` для предотвращения циклических импортов и дублирования логов. Бот запустит бесконечный цикл поллинга с реконнектом при ошибках сети (таймаут 15 сек).*

## 🛠️ Подробная конфигурация (`config.py`)

Файл `config.py` — декларативный мозг бота. Изменения требуют перезапуска.

### 📡 Telegram и Сеть
- **`BOT_TOKEN`** — Токен бота от @BotFather.
- **`ALLOWED_ID`** — Твой Telegram ID (целое число). Бот будет отвечать только тебе.
- **`PROXY_URL`** — Адрес SOCKS5/HTTP прокси (напр. `socks5://user:pass@host:port`). Если не нужна, оставь пустой строкой.
- **`REQUEST_TIMEOUT`** — Таймаут ожидания ответа от Telegram (по умолчанию `120`). Увеличь, если бот часто отваливается по таймауту из-за медленного прокси.

### 📂 Пути к хранилищу
- **`VAULT_PATH`** — Абсолютный путь к корню хранилища.
- **`BASE_FOLDER`** — Имя корневой папки для задач внутри хранилища (например, если все рабочие папки лежат в `Obsidian/Tasks/`, укажи `"Tasks"`).

### 🌍 Часовой пояс
- **`TIMEZONE`** — Таймзона IANA (например, `"Europe/Moscow"`, `"Asia/Yekaterinburg"`). 
  - *Use case:* Если сервер стоит в Европе, а ты живешь на Урале, укажи `"Asia/Yekaterinberg"`, и бот будет присылать уведомления по твоему времени.
  - Если оставить пустым `""`, бот будет использовать системное время машины.

### ⚙️ Логика работы бота

- **`PAGINATION_LIMIT`** — Количество заметок, выводимых на одной странице (по умолчанию `5`). Работает и для списка статусов, и для дедлайнов.
- **`INACTIVE_STATUSES`** — Черный список статусов. Заметки с этими статусами бот *игнорирует* при поиске дедлайнов для уведомлений. По умолчанию: `["Done", "Archive"]`.
- **`ACTIVE_STATUSES`** — Белый список статусов. Имеет **приоритет над `INACTIVE_STATUSES`**. Если список не пуст, бот будет присылать уведомления *ТОЛЬКО* по этим статусам. По умолчанию: `["Current", "In Progress", "Backlog", "Constant"]`.
  - *Use case:* У тебя сложная система статусов, и ты хочешь, чтобы бот нотифицировал только по задачам в работе, игнорируя всё остальное, даже если статус не в `INACTIVE_STATUSES`.
- **`OVERDUE_DAYS_LIMIT`** — За сколько дней показывать просроченные задачи (по умолчанию `30`).
  - *Use case:* Если поставить `30`, кнопка «🔴 Просрочено» покажет задачи, дедлайн которых прошел за последние 30 дней. Старые задачи не будут засорять список.

### 🏷️ Имена свойств в Obsidian (YAML)

- **`DUE_FIELDS`** — Список полей, где бот ищет дату дедлайна. Ищет по порядку, берет первую найденную. По умолчанию: `["due", "deadline", "finish_date"]`.
  - *Use case:* Если в части заметок ты используешь `due`, а в другой `deadline`, бот найдет обе. Этот же список используется для инлайн-полей Dataview (DRY).
- **`CREATED_FIELDS`** — То же самое, но для даты создания. По умолчанию: `["created", "creation_date"]`.
- **`HIDDEN_FIELDS`** — Служебные поля YAML, которые не нужно выводить в карточку заметки в Telegram. По умолчанию: `["position", "kanban-plugin"]`.
  - *Use case:* Сюда можно добавить `id`, `creation_date` или любые другие свойства, чтобы карточка в Telegram была компактной.

### 🗑️ Черный список, Тихие часы и Сводки

- **`IGNORE_TAGS`** — Список тегов. Заметки с этими тегами бот полностью проигнорирует (даже если у них есть дедлайн). По умолчанию: `["no_bot", "ignore"]`.
  - *Use case:* Поставь тег `#no_bot` в заметку, и бот перестанет о ней напоминать. Не добавляйте сюда `archive`, иначе бот не сможет отображать архивные задачи по кнопке!
- **`QUIET_HOURS`** — Кортеж часов, в которые уведомления *не отправляются* (если тихие часы включены пользователем в боте). По умолчанию: `(23, 8)` (с 23:00 до 08:00). Считаются в TIMEZONE!
- **`DIGEST_TIME`** — Время отправки утренней сводки в формате строки (если сводка включена пользователем в боте). По умолчанию: `"09:00"`. Задача в планировщике просыпается ровно в эту минуту, не нагружая процессор постоянными проверками.

### 🚦 Приоритеты (Сортировка)

- **`ENABLE_PRIORITY_SORT`** — Включить (`True`) или выключить (`False`) сортировку по приоритету. По умолчанию: `False`. 
  - *Логика:* Если включено, бот использует кортеж `(дата, приоритет)` при сортировке. Время остается главнее! Приоритет применяется только как вторичный ключ, когда у нескольких задач совпадает дата и время до минуты.
- **`PRIORITY_SOURCES`** — Словарь, определяющий, где бот будет искать приоритет (каскадный поиск: сначала YAML, затем название, затем тело).
  ```python
  PRIORITY_SOURCES = {
      "yaml": True,      # Искать в свойствах (например, priority: Highest)
      "title": True,     # Искать в названии файла (например, ⏫ Срочный проект)
      "body": False      # Искать в тексте/чекбоксах
  }
  ```
- **`PRIORITY_MAP`** — Карта приоритетов. Бот приводит текст к нижнему регистру и ищет совпадение. Возвращает число (чем меньше, тем выше приоритет). 
  ```python
  PRIORITY_MAP = {
      "⏫": 0, "highest": 0,
      "high": 1,
      "🔼": 2, "medium": 2,
      "⏬": 4, "lowest": 4, "very low": 4,
      "🔽": 3, "low": 3
  }
  ```

### 🔍 Гибкий поиск дат (Атомарные тумблеры)

Поиск настраивается отдельно для *источников* (где искать) и *маркеров* (что считать дедлайном). Дата будет найдена только если включен её источник И включен хотя бы один маркер.

**Источники (где искать):**

- **`SEARCH_PROPERTY`** — Искать в YAML-свойствах заметки (поля из `DUE_FIELDS`). По умолчанию: `True`.
- **`SEARCH_CHECKBOX`** — Искать в чекбоксах (`- [ ] текст` и `- [x] текст`). Если включено, выполненный чекбокс `[x]` гасит пуш (задача выполнена). По умолчанию: `True`.
  - *Use case:* Если выключить (`False`), бот "не увидит" крестик `[x]` и всё равно пришлет уведомление. Override делает только этот тумблер.
- **`SEARCH_LIST`** — Искать в обычных списках (`- текст`, `* текст`, `1. текст`, `12) текст`). По умолчанию: `False`.
- **`SEARCH_BODY`** — Искать в любых других строках текста. По умолчанию: `False`.
  - *Use case:* Включай только если у тебя даты вписаны в обычные предложения. Это может дать ложные срабатывания.

**Маркеры (что считать дедлайном):**

- **`ENABLE_TASKS_EMOJI`** — Распознавать эмодзи плагина Tasks (`📅`, `⏳`, `🛫`). Работают и ДО, и ПОСЛЕ даты. По умолчанию: `True`.
- **`TASKS_DUE_EMOJI`** — Список эмодзи, которые считаются маркерами дедлайна. По умолчанию: `["📅", "⏳", "🛫"]`.
  - *Use case:* Если ты используешь `⏳` как `scheduled` и не хочешь, чтобы бот на него реагировал, убери его из списка, оставь только `["📅", "🛫"]`. Служебные эмодзи (приоритеты ⏫/🔼/🔽, recurring 🔁, created ➕) НЕ включены в дефолт.
- **`ENABLE_DATAVIEW`** — Распознавать инлайн-поля Dataview (`due:: 2026-08-09` и `[due:: 2026-08-09]`). Имена полей берутся из `DUE_FIELDS`. По умолчанию: `False`.
- **`ENABLE_BARE_DATES`** — Распознавать "голую" дату без маркеров. Ищется **СТРОГО В КОНЦЕ СТРОКИ** — это защита от ложных срабатываний. По умолчанию: `True`.
  - *Use case:* Строка `- Сдать отчет 2026-08-15` распознается, а строка `- В 2026-08-15 году` — нет (дата не в конце).

### 📆 Форматы дат и времени

Бот автоматически генерирует все комбинации форматов и разделителей при старте.

- **`DATE_FORMATS`** — Шаблоны дат. `%Y` (год), `%m` (месяц), `%d` (день). По умолчанию: `["%Y%m%d", "%d%m%Y"]`.
- **`TIME_FORMATS`** — Шаблоны времени. `%H` (часы), `%M` (минуты), `%S` (секунды). По умолчанию: `["%H%M%S", "%H%M", "%H"]`.
- **`DATE_DELIMITERS`** — Разделители для дат. По умолчанию: `["-", ".", "/", ":", "_", " "]`.
- **`TIME_DELIMITERS`** — Разделители для времени. По умолчанию: `["-", ".", "/", ":", "_", " "]`.
  - *Use case:* С дефолтными настройками бот поймет и `2026-08-09`, и `09.08.2026`, и `09/08/2026`, и `20260809`.

### 👁️ Настройки отображения

- **`SHOW_SOURCES`** — Группировать задачи по источникам (Projects, Kanban, Tasks) в меню **📅 Дедлайны**. Если `False`, выводит сплошным списком. По умолчанию: `True`.
- **`SHOW_PROPERTIES`** — Показывать свойства (YAML frontmatter) в карточке заметки. По умолчанию: `True`.
- **`SHOW_BODY`** — Показывать текст (тело) заметки. По умолчанию: `True`. Бот попытается сохранить отступы списков через невидимые символы Брайля, а заголовки `##` заменит на жирный текст с 📌.
- **`SHOW_EMPTY_PROPERTIES`** — Показывать пустые свойства (выведет `ключ: -`). По умолчанию: `False`.

### 📋 Настройки Kanban

В боте доступно отдельное меню настроек Kanban (Кнопка "📋 Kanban"):
- **Сортировка:** Сначала новые (свежие даты) / Сначала старые (древние даты).
- **Направление:** Сверху вниз / Снизу вверх.
- **Группировка:** 
  - `С группировкой` (Переключатель. Включает разделение списка на доски и обычные заметки. Если включено, активны кнопки выбора порядка).
  - `Сначала борды` (доски плагина Kanban выводятся выше обычных заметок).
  - `Сначала заметки` (обычные заметки выше досок).
- В `config.py` за сканирование обычных заметок в папке Kanban отвечает `parse_regular_notes: True` внутри словаря `SOURCES`.

### ⚙️ Дополнительные настройки

В боте есть отдельное меню (Кнопка "⚙️ Дополнительные настройки"):
- **🌅 Утренняя сводка:** Переключатель. Если включено, каждый день в `DIGEST_TIME` бот будет присылать одно большое сообщение со списком задач на сегодня и просроченных.
- **🌙 Тихие часы:** Переключатель. Если включено, бот не будет присылать пуши в часы, указанные в `QUIET_HOURS`.

### 🆕 Дополнительные параметры отображения и логирования (в `config.py`)

- **`LOG_LEVEL`** — Уровень логирования: `"INFO"` (базовый), `"DEBUG"` (подробный, для поиска ошибок), `"WARNING"` (только ошибки). По умолчанию: `"INFO"`.
- **`HIDE_COMPLETED_IN_DEADLINES`** — Скрывать выполненные (статусы из `INACTIVE_STATUSES`) задачи из списков "Дедлайны", "Просроченные" и "Утренняя сводка". По умолчанию: `True`. (В самих проектах и канбан задачи остаются видимыми).
- **`DEADLINES_DAY_VIEW`** — Режим для кнопок периода в Дедлайнах: `"24h"` (скользящее окно от текущего времени) или `"today"` (до 23:59 нужного дня). По умолчанию: `"24h"`.
- **`DIGEST_DAY_VIEW`** — Режим для утренней сводки: `"24h"` или `"today"`. По умолчанию: `"today"`.

### 🗂 Источники данных (`SOURCES`)

Словарь, где настраиваются папки для парсинга. Ключ — внутренний идентификатор.

- **`enabled`** — Включить (`True`) или выключить (`False`) источник.
- **`folder`** — Имя папки внутри `BASE_FOLDER` (или абсолютный путь, если начинается с `/`).
- **`name`** — Имя, которое будет отображаться в Telegram.
- **`order`** — Статический порядок вывода в **📅 Дедлайны** (1 — сверху, 2 — ниже и т.д.), если выключена динамическая сортировка.
- **`icon`** — Иконка источника для заголовков и групп (приоритетная настройка).

**Как добавить свой источник (например, "Идеи"):**
1. Добавь в словарь `SOURCES`:
   ```python
   "ideas": {
       "enabled": True,
       "folder": "Ideas",
       "name": "Идеи",
       "order": 4,
       "icon": "💡"
   }
   ```
2. Добавь кнопку в `SOURCE_BUTTONS` (см. ниже): `"💡 Идеи": "ideas"`.
3. *Опционально:* Если это источник-список (как Tasks), где нужно выводить только заметки с чекбоксами/датами, раскомментируй строку в `obsidian_parser.py` (инструкция есть в самом конфиге).

### 📁 Как добавить новый проект (с уникальными статусами)

Бот поддерживает создание неограниченного количества независимых проектов внутри папки `Projects`. Папка `Projects` работает как **контейнер**.

**Шаг 1. Создай папку в Obsidian**
Внутри своей папки `Tasks/Projects/` создай новую подпапку для проекта. Например, `Study` (Учеба).
Путь должен выглядеть так: `Tasks/Projects/Study/`.

**Шаг 2. Настрой статусы в `config.py`**
Открой `config.py`, найди переменную `STATUS_BUTTONS` и добавь туда новый блок, где **ключом будет точное имя созданной папки**.

```python
STATUS_BUTTONS = {
    # Статусы по умолчанию (для проектов без уникальных статусов)
    "_default": {
        "🔁 Constant": "Constant",
        "📥 Backlog": "Backlog",
        "🎯 Current": "Current",
        "⏳ In Progress": "In Progress",
        "✅ Done": "Done",
        "📦 Archive": "Archive"
    },
    # Уникальные статусы для проекта "Study"
    "Study": {
        "📖 To Learn": "To Learn",
        "📝 Practicing": "Practicing",
        "🧠 Learned": "Learned"
    }
}
```

**Как это работает:**
1. Ты нажимаешь кнопку **📁 Projects** в Telegram.
2. Бот сканирует папку `Projects/`, находит подпапки и выдает меню выбора (если их больше одной).
3. При выборе проекта `Study` бот отобразит задачи только из этой папки и нарисует кнопки статусов **только для этого проекта** (`To Learn`, `Practicing`, `Learned`).
4. Если ты создашь папку `Work`, но забудешь добавить её в `config.py`, бот не упадет с ошибкой — он просто подтянет для этого проекта стандартные статусы из блока `"_default"`.

### 🎨 Иконки и Кнопки

- **`SOURCE_ICON`** — Иконка по умолчанию (fallback), если для источника не задана своя. По умолчанию: `📂`.
- **`CARD_ICON`** — Иконка перед названием файла в карточке. По умолчанию: `🗂`.
- **`CHECKBOX_UNCHECKED`** / **`CHECKBOX_CHECKED`** — Иконки для чекбоксов при выводе в Telegram. По умолчанию: `◻️` и `☑️`.

- **`STATUS_BUTTONS`** — Словарь кнопок статусов для плагина Projects. Формат: `"Текст на кнопке": "Название статуса в YAML"`.
  - Ключ верхнего уровня — имя папки проекта (или `"_default"` для всех остальных).
  - Внутри — словарь кнопок формата `"Текст на кнопке": "Название статуса в YAML"`.
  - *Правило:* Эмодзи берется из текста кнопки (всё ДО названия статуса). Бот автоматически разбивает кнопки по 3 в ряд.

- **`SOURCE_BUTTONS`** — Словарь кнопок дополнительных источников (Kanban, Tasks и свои). Формат: `"эмодзи Название": "ключ из SOURCES"`.
  - Кнопка появляется в главном меню только если источник `enabled`. Эмодзи (всё до первого пробела) подставится в заголовок и шапку группы.

## 📝 Использование

### Просмотр дедлайнов
Нажми кнопку **📅 Дедлайны** в главном меню. По умолчанию откроются задачи на 1 день вперед.
Внизу экрана 8 кнопок-периодов:
- `1 день` / `2 дня` / `4 дня` / `Неделя`
- `2 недели` / `Месяц` / `Все` / `🔴 Просрочено`

В настройках (**📊 Настройки дедлайнов**) можно выбрать:
- Порядок сортировки (🆕 Сначала новые / 📅 Сначала старые)
- Направление списка (⬇️ Сверху вниз / ⬆️ Снизу вверх)
- Группировку по источникам (🔀 Группировка)
- Динамическую сортировку групп (⚡️ Группы в порядке срочности)

В меню **🛎️ Уведомления** можно:
- Настроить интервалы срабатывания (5 мин, 1 час, за день и т.д.).
- Включить уведомление "В момент начала".
- Включить **🔕 Беззвучные уведомления** (пуши без звука и вибрации).

### Пример заметки (YAML Frontmatter)
```yaml
---
status: Current
due: 2026-08-09 18:00
created: 2026-08-09
---
```

## 🛠️ Логирование и Отказоустойчивость

В начале файла `bot.py` находится переменная `LOG_LEVEL`:
- `logging.INFO` — базовый режим (только важные события и ошибки).
- `logging.DEBUG` — подробный режим (показывает каждую проверяемую заметку и процесс нотификации). 

Логи пишутся в файл `bot.log` (ротация: максимум 3 файла по 5 МБ).

**Защита данных:**
- Если файл `settings.json` поврежден (например, обнулился при сбое питания), бот создаст бэкап `settings.json.corrupted_backup` и начнет с чистого листа.
- Сохранение настроек происходит атомарно: данные сначала пишутся во временный файл `.tmp`, и только при успехе заменяют основной файл (`os.replace`).
- При потере сети бот уйдет в бесконечный цикл реконнектов с интервалом 15 секунд, не падая критически.
